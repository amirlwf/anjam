# Implementation Plan: Anjam v1.4.0 — Quality, Parity & Smarts

**Branch**: `001-v140-quality-parity` | **Date**: 2026-09-25 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-v140-quality-parity/spec.md`

## Summary

One release that makes Anjam genuinely good on a phone and noticeably smarter:
fix the Android scroll / FAB / overflow defects (P1), add a 21:00–08:00 weather
advice engine that only speaks when it matters (P1), replace the clock-based
class timetable with a period-based weekly grid (P1), lift the whole UI to an
Apple-grade finish with a bigger logo, six full themes and a weather-reactive
variable theme (P2), add local backup + restore (P2), and monitor location-aware
school news with a 21:00 closure popup (P3). Approach: extend the existing
single-CSS design system and keyless-fetch stack instead of adding
dependencies; add four plain-TypeScript modules (`advisory.ts`, `news.ts`,
`backup.ts`, `themes.ts`) and an additive, idempotent schema migration.

## Technical Context

**Language/Version**: TypeScript 5.5, React 18.3, Vite 5.4 (`npm run build` = `tsc --noEmit && vite build`)

**Primary Dependencies**: `@capacitor/core` 6 + `@capacitor/android`, `@capacitor/local-notifications` 6, `@capacitor/status-bar` 6, `@supabase/supabase-js` 2, `jalaali-js`, `vazirmatn`. No new runtime dependency planned (news XML parsed with `DOMParser`, theme tokens hand-rolled).

**Storage**: IndexedDB `anjam` (one object store per table + `outbox` + `meta`), `localStorage` for `anjam.*` prefs, optional Supabase Postgres with idempotent `supabase/schema.sql` (RLS + realtime publication).

**Testing**: `scripts/cdp-ux-check.mjs` CDP harness against `vite preview` (extended past the current checks, target `failed:[]`), `python scripts/sql-lint.py` (pglast) for schema, `apksigner verify` for the APK, `scripts/verify-release.mjs` for release integrity.

**Target Platform**: Android 8+ WebView (Capacitor 6), Windows 10/11 (Electron 31), modern browsers at 360–1440 px.

**Project Type**: Single Vite SPA shipped in two shells (`src/` shared, `android/`, `electron/`).

**Performance Goals**: 60 fps motion (transform/opacity only), one contained scroll container per view, weather/news fetches ≤ 20 s and never blocking paint, advisory evaluation < 50 ms.

**Constraints**: keyless public data sources only; fa+en for every string; silent network degradation; bundle growth accepted (quality over size) but no dead code.

**Scale/Scope**: 12 views, 11 IndexedDB stores, ~10k LOC; this feature touches ~20 files plus 4 new modules.

**Structure Decision**: single shared SPA (`src/`) inside two shells — no new
packages, no backend. New behaviour lands as focused `src/lib/*.ts` modules with
UI in `src/components/*.tsx`, matching the existing architecture so the QA
harness, sync pipeline and alarm engine keep working unchanged.
