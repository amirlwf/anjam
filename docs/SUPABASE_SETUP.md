# راهنمای راه‌اندازی Supabase (۵ دقیقه)

اپ «انجم» برای همگام‌سازی بین ویندوز و اندروید به یک پروژه‌ی Supabase نیاز دارد.
هر دو دستگاه با **یک حساب** وارد می‌شوند و داده‌ها از طریق Postgres + Realtime رد و بدل می‌شود.

## ۱) ساخت پروژه

1. وارد [supabase.com](https://supabase.com) شوید → **New project**.
2. یک رمز دیتابیس ذخیره کنید، نزدیک‌ترین منطقه را بزنید.

## ۲) اجرای اسکریپت دیتابیس

1. در پنل پروژه به **SQL Editor** بروید → **New query**.
2. کل محتوای فایل [`supabase/schema.sql`](../supabase/schema.sql) را کپی کنید و **Run** بزنید.

اسکریپت سه جدول `lists`، `labels`، `tasks` به‌همراه ایندکس، سیاست‌های RLS
(هر کاربر فقط داده‌ی خودش را می‌بیند) و فعال‌سازی Realtime را می‌سازد.
اجرای چندباره‌اش مشکلی ایجاد نمی‌کند.

## ۳) فعال‌سازی ورود بدون تأیید ایمیل (اختیاری ولی پیشنهادی)

1. **Authentication → Sign In / Up → Providers → Email**
2. گزینه‌ی **Confirm email** را خاموش کنید تا بلافاصله وارد شوید.
   (اگر روشن بماند، بعد از Sign up باید لینک تأیید ایمیل را باز کنید.)

## ۴) کپی کردن کلیدها

1. **Project Settings → API**
2. دو مقدار را کپی کنید:
   - **Project URL** → مثلاً `https://abcdefgh.supabase.co`
   - **anon public** key → شروع با `eyJhbGciOi...`

## ۵) وارد کردن در اپ

1. اپ Anjam را در ویندوز یا اندروید باز کنید.
2. دکمه‌ی ⚙ **Settings** (یا صفحه‌ی اولِ اتصال) → آدرس و کلید را بچسبانید.
3. **Test connection** → باید `Connection OK` بدهد (یعنی اسکریپت SQL درست اجرا شده).
4. **Connect** سپس با ایمیل و رمز **Sign up** کنید.
5. روی دستگاه دیگر هم همین مراحل را با **همان ایمیل** تکرار کنید → همگام‌سازی خودکار شروع می‌شود.

## عیب‌یابی

| پیغام | دلیل / راه‌حل |
|---|---|
| `relation "public.lists" does not exist` | اسکریپت `schema.sql` اجرا نشده. |
| `Invalid API key` | کلید یا آدرس اشتباه است (Project Settings → API). |
| `Invalid login credentials` | رمز اشتباه؛ یا Confirm email روشن است و ایمیل تأیید نشده. |
| داده روی دستگاه دوم نمی‌آید | در SQL Editor دوباره بلوک آخر `schema.sql` (realtime) را اجرا کنید و در اپ **Sync now** بزنید. |
| خطای `JWT expired` | اینترنت را چک کنید؛ اپ خودکار رفرش می‌کند، اگر پابرجا بود از حساب خارج و دوباره وارد شوید. |

## نکته‌های امنیتی

- سیاست‌های RLS فعال است: بدون لاگین هیچ داده‌ای خوانده/نوشته نمی‌شود.
- کلید `anon` عمومی است و تا زمانی که RLS درست باشد مشکلی ندارد؛ هرگز کلید `service_role` را در اپ قرار ندهید.
- همگام‌سازی بر مبنای `updated_at` است (Last-Write-Wins): تغییر جدیدتر، برنده‌ی نهایی.
